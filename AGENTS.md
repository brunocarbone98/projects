# AGENTS.md

Instructions for any coding agent — Claude Code, Codex, Cursor, Copilot — working in this repository; the same rules apply to humans. Claude Code sessions also load `CLAUDE.md`, which imports this file.

## Map

- `FullStackHub/` — **Shipping Hub**, a bilingual (es/en) parcel shipping & tracking platform: Next.js 16 web (`apps/web`), Express 5 + Prisma API (`apps/api`, the only layer touching PostgreSQL), two stateless FastAPI services (`services/pricing`, `services/labels`), shared Zod contracts (`packages/shared`); pnpm 10 workspaces + Turborepo. Live on Railway as one container (root `Dockerfile`, `start.sh`, `railway.json`).
- `SecureGate/` — the black-box QA & security suite for Shipping Hub: Java 21, Maven (`./mvnw`), Karate API features, Serenity BDD + Screenplay over Selenium for UI, Cucumber, a Postman/Newman collection, a token-gated SonarQube gate.
- `DramaFetch/` — **DramaFetch**, a TikTok short-drama series downloader for personal offline viewing: Python 3.11+, Playwright discovers the episode list, yt-dlp (or, with `--engine browser`, one Chromium session reusing the list's play URLs) downloads each episode, paced like one person watching, a stdlib `http.server` web UI; episodes the account has not unlocked are listed and skipped, never unlocked; paid episodes it has unlocked download like free ones.
- `DramaFetch/extension/` — **DramaFetch for Chrome**, the same downloader as a Manifest V3 extension for users without Python (Windows first, installed with **Load unpacked**): plain ES2022 modules with `// @ts-check` and JSDoc, no npm dependencies, no remote code; it re-implements the engine with the Python tool's rules, texts and constants (a parity test compares them) and downloads only what TikTok serves to the user's own logged-in Chrome session — it never reads cookies, never patches, wraps or overrides anything in TikTok's page (it only runs the page's own `fetch`, scrolls the list and reads the visible text there; since 2.0.0 it has no content script and no right-click menu) and never changes the page's requests. Its library (1.6.0) keeps the user's TikTok Favorites → Drama list across sessions with TikTok's own count and feeds the ticked series ids — or one card's, with its **Download** (1.7.0) — to the same download engine, which a pasted link (1.7.0: no button) feeds the same way; what a drama's download could not save for a reason a retry can change it retries once on its own (1.8.0, the owner's request of 2026-11-21: the tab's own **Retry**, queued at the end of the queue, never after a stop or during the cooldown) and says so in its alerts; the one exception to "nothing in TikTok's page", the owner's decision of 2026-11-19: on the user's explicit request and confirmation, for a drama its records show complete on disk, it presses TikTok's own Bookmark button once on that drama's page (in a muted background tab it opens and closes) and verifies the removal after a reload; the owner's decision of 2026-11-22 (2.0.0) extends it: the same press on its own once every episode of a drama of the library is on disk — after its automatic retry when it needed one —, queued at the end of the queue — next, right after the listing, for the one a listing of the drama leads to, queued once when a removal's episode count was more than a day old at its turn — (the **Remove a drama from my Favorites once all its episodes are downloaded** setting, on by default), never after a stop or during the cooldown, and none after TikTok did not keep or refused a removal until the tab is reloaded — it never sends, builds or replays TikTok's `collect` request itself.
- `PersonalWebsite/` — static two-page portfolio (`MainPage.html`, `Portfolio.html`, `favicon.svg`), vanilla HTML/CSS/JS, served by GitHub Pages.

Per-project instructions: `FullStackHub/CLAUDE.md`, `SecureGate/CLAUDE.md` and `DramaFetch/CLAUDE.md` (rules and commands; each also names its project's subagents, defined in that project's `.claude/agents/`) — read the one for the folder you change before you start. Deployment: `DEPLOY.md`. Agents, shifts and incidents: `OPERATIONS.md`. Never edit `FullStackHub/ROADMAP.md` or `SecureGate/ROADMAP.md`.

## Conventions

- Everything in English: code, comments, commits, docs. UI copy lives in the `next-intl` message files (`apps/web/messages/*.json`, both languages), never hardcoded.
- Conventional commits in the imperative: `feat:`, `fix:`, `chore:`, `docs:`, `refactor:`, `test:`, `ci:`, `revert:` (the merge gate's reverts).
- Strict TypeScript everywhere; `any` is forbidden; validate external input with Zod at the edge; shared contracts live in `packages/shared` and are never duplicated.
- Prettier (printWidth 100) is mandatory for every `.ts/.tsx/.md/.json/.yml` under `FullStackHub/`: `pnpm --dir FullStackHub exec prettier --write <files>`. Ignored on purpose: `ROADMAP.md`, `pnpm-lock.yaml`, `apps/web/src/lib/world-coastlines.ts`.
- Python services: type hints everywhere, Pydantic models are the contract, tests with pytest in each service's `.venv`.
- DramaFetch: Python 3.11+ with type hints everywhere; `ruff check`, `ruff format --check` and `mypy --strict` must pass (`DramaFetch/pyproject.toml`, rules never loosened); pytest runs against fixtures and the local fake TikTok server — nothing reaches tiktok.com from a sandbox or CI; parsing is pure functions, the network layer is thin and injectable, no runtime dependencies beyond yt-dlp, Playwright and mutagen (pure Python; it writes each episode's cover into the MP4); never log cookie values, never bypass paywalls, DRM or anti-bot checks (the only automation-related settings are a Chrome user agent without `Headless` and curl_cffi's Chrome TLS impersonation, listed in `DramaFetch/CLAUDE.md`; Chromium runs with its default flags; no proxies, no stealth plugins).
- DramaFetch's Chrome extension (`DramaFetch/extension/`): plain ES2022 modules with `// @ts-check` and JSDoc types, checked by the strict `checkJs` run of `tsc`; no npm dependency (Node built-ins only in its tests) and no remote code (CSP `script-src 'self'; object-src 'self'`); its texts, constants and decisions are the Python tool's, proven by the parity tests (`DramaFetch/tests/test_extension_parity.py`, `test_extension_media.py`) — a rule changes in both front ends or in neither. Its only header changes are on its own media, cover and thumbnail requests — `Referer: https://www.tiktok.com/` set and `Origin` removed, by one declarativeNetRequest session rule whose initiator is the extension itself; `chrome.webRequest` is observation only (the series tab's list requests, the favorites-list requests of the user's TikTok tabs — URL and status, the first page's address kept in `chrome.storage.session` —, the redirects answered to its own requests, the status of the `…/collect/` request a drama's page sends when DramaFetch presses its Bookmark, and of that page's own episode-list requests — a 429 there is a refusal, as for a listing); nothing is pressed in TikTok's page but that Bookmark button, once per removal — on the user's confirmed request (the owner's decision of 2026-11-19, `src/app/bookmark.js`) or, since 2.0.0, on its own (the owner's decision of 2026-11-22, `queueAutoRemoval` in `src/app/app.js`, the **Remove a drama from my Favorites once all its episodes are downloaded** setting): only for a drama the library holds whose download job's run did not stop, every episode on disk and none locked, protected by DRM, served short or missing, never while a cooldown is in force or after a refused write, at the end of the queue with the rest between jobs (the one a re-listing of its drama leads to — `queueRelist`, once per removal whose episode count was more than a day old at its turn — next, right after that listing), **Stop** taking the waiting ones out at once, and none after a removal TikTok did not keep, confirm or refused until the tab is reloaded; no signed URL (the favorites address, cover URLs) in `chrome.storage.local`; no content script and no `contextMenus` (2.0.0 removed the right-click items and their favorites card reader), and its `runtime.onMessage` handlers hear only the extension's own pages and worker; its alerts when a drama is done and when its own removal of a drama from the Favorites ends (`notifications`, the newest permission — the owner's request of 2026-11-19, `src/app/alerts.js`) are plain text the DramaFetch tab makes — never an address, a cookie or a signed parameter —, and a click on one makes the worker ask nothing of TikTok: their **Retry** queues only what the tab's own **Retry** queues; its one automatic retry (1.8.0, `queueAutoRetry` in `src/app/app.js`, the **Retry on its own what did not download** setting) is that same **Retry** queued once for a drama's plain failures — never after a stop of that drama's run (a refusal, the cooldown, three failures in a row, **Stop** — even one pressed while the job's last episode transfers —, a refused write), never while a cooldown is in force, never for an automatic retry's own failures or for episodes a waiting `selection` job of the drama (a retry, **Download selected**, **Download all available**) or the running one not yet done with that drama holds, with no timer and no `alarms`; **Stop** takes the waiting automatic retries out of the queue at once; no `cookies` permission, no `chrome.debugger`, and no new permission or host permission without a human decision.
- SecureGate: black-box only (public API and UI, never source or database); Screenplay for UI with no selectors in step definitions; Karate for API with `match` contracts; explicit waits only, never `Thread.sleep`.

## Definition of done

1. The relevant checks above ran and are green, with real output or counts in the PR. A SecureGate run whose `target/surefire-reports/*.xml` says `tests="0"` did not run — say so. For `DramaFetch/`, green means `ruff check`, `ruff format --check`, `mypy` and `pytest` all pass (plus `pytest -m integration` when a Chromium is available), and so does `cd DramaFetch/extension && node --test && npx -y -p typescript@5.9.3 tsc -p jsconfig.json`.
2. Prettier left no diff under `FullStackHub/`; no lint rule loosened, no test skipped, no `any` added.
3. Documentation that states what you changed — README, the CLAUDE.md files, `OPERATIONS.md`, counts, commands, links — is updated in the same PR; a DramaFetch change users can see also bumps its version and adds a `DramaFetch/CHANGELOG.md` entry (`DramaFetch/CLAUDE.md` → Conventions).
4. The PR follows `.github/pull_request_template.md`: Summary · Changes · How I verified · Risks & rollback · `Opened by:`.
5. Nothing secret in the diff, the logs or the PR body.

## Guardrails

1. Never push to `main`. Always a branch + a pull request. Never force-push or rewrite history. Only `merge-steward`, inside the merge gate shift (`.claude/shifts/merge-gate.md`), merges a pull request: a Dependabot or agent PR that passes that gate, or its own revert when `main` turns red after one of its merges. No other agent merges; a person's PR, and anything the gate escalates, is merged by a human.
2. One PR per shift run, small and reviewable (aim for under 200 changed lines excluding lockfiles). If nothing is needed, do nothing: no empty PRs, no "all good" issues or comments.
3. Run the project's own checks before opening a PR (FullStackHub: `pnpm lint && pnpm format:check && pnpm typecheck && pnpm test`; services: `pytest`; SecureGate: `./mvnw -q verify` when a local stack is up; DramaFetch: `ruff check`, `ruff format --check`, `mypy` and `pytest`, plus `pytest -m integration` when a Chromium is available, and the extension's `node --test` and `npx -y -p typescript@5.9.3 tsc -p jsconfig.json`). Report the real results.
4. Never weaken, skip or quarantine a test, loosen a lint rule, or add `any` to get green.
5. Respect each project's architectural rules (Shipping Hub: only `apps/api` touches the DB; `tracking_events` and `ledger_entries` are append-only; state transitions come from `packages/shared`; every money operation has an `idempotency_key` + transaction; public endpoints are rate-limited. SecureGate: black-box only; Screenplay for UI; Karate for API; explicit waits only).
6. Never commit or print secrets; use the seeded demo accounts only against local or CI stacks.
7. Report truthfully: failing is failing (with output), skipped is skipped (SecureGate skips when the stack is down — a run with 0 failures and N skipped is NOT a pass).
8. When a change needs a human decision (schema, money, auth, deploy config, dependency majors), open an issue instead of guessing.

## Branches, PRs and issues

- Branches for agent work: `agents/<shift>/<YYYY-MM-DD>`, e.g. `agents/nightly-maintenance/2026-10-29`; the merge gate's reverts use `agents/merge-gate/<YYYY-MM-DD>-revert-<N>`. Humans use any descriptive branch name.
- PR titles are conventional commits: `chore(agents): nightly maintenance 2026-10-29`, `fix(agents): …`, `docs(agents): …`, `chore(deps): …`, `revert(agents): #<N> — …` (the merge gate). Every agent PR carries the `agent` label and fills the template's `Opened by:` line with the shift name.
- Labels: `agent` (work by/for agents) · `incident` (uptime) · `dependencies` (Dependabot) · `security` · `maintenance` · `bug` · `in progress` · `do-not-merge` (the merge gate never merges a PR that carries either).
- Issue titles: `🚨 Production incident: Shipping Hub is unhealthy` (label `incident`; opened, updated and closed by the Uptime patrol workflow) · `🧪 Nightly maintenance failed: <YYYY-MM-DD>` (labels `agent`, `maintenance`) · `🚦 Merge gate reverted #<N>: <YYYY-MM-DD>` (labels `agent`, `maintenance`; opened by the merge gate when `main` turned red after one of its merges, next to its revert PR) · `🎬 DramaFetch needs a decision: <topic>` (labels `agent`, `maintenance`; one per topic, for what `download-guardian` leaves to a human — an open one gets a comment with the new evidence, never a second issue) · `🔐 Weekly security review: <YYYY-MM-DD>` (labels `agent`, `security`).
- To ask the on-call agent for something, mention `@claude` in an issue or PR comment, or open an issue with the "Ask the on-call agent" template (`.github/ISSUE_TEMPLATE/agent-task.yml`).
- Merging: only the merge gate (`.claude/shifts/merge-gate.md`, daily at 11:47 UTC, after the maintenance shifts) merges, through `merge-steward`, and only Dependabot and agent PRs that pass its gate; a human merges the rest. Agents never force-push, never rewrite history.
