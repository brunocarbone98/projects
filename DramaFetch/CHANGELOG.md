# Changelog

One version for the whole of DramaFetch — the Python tool (`pyproject.toml`, `dramafetch --version`) and the Chrome extension (`extension/manifest.json`, shown in `chrome://extensions` and next to the title of the DramaFetch tab and the popup). Every change users can see ships with a new number: a new feature raises the middle number (1.2.0 → 1.3.0), a fix the last one (1.2.0 → 1.2.1). Dates are the day the version was finished.

## 1.3.0 — 2026-11-07

- Free series with conditions are read right. A series TikTok marks `isLimitedFree: true` — free, with conditions the field does not name — listed every episode as `locked` with hints such as `isFree=false; IsPreview=True; PreviewType=4`, so **Download all available** downloaded nothing and the Python tool skipped everything: `IsFreeIntro` ("is this the free intro teaser"), `IsPreview` and `PreviewType` say nothing about what your session may play — the owner's real list of 2026-11-06 had them on fully served episodes too — and they no longer count as locks or prices. Such a series now lists as `free` and downloads with one click; its hint `isLimitedFree=True` appears only next to a price (`unlockPrice`), where it says why a sold episode is free.
- A short header is told before any request. Some episodes come as a file that is the whole episode by size but whose header plays only part of it — about 70 s of a 106 s episode — and the list gives it away: the episode's own sound (`music.duration`) is far shorter than the episode (`video.duration`). That can be a window for an episode your account has not unlocked, or a defective encode on TikTok's side — the owner's 7 episodes of 2026-11-06 broke at the same point in the TikTok app and in TikTok's web player: no sound past it, a broken picture when seeking past it — and the list cannot tell the two apart. Such an episode is listed `locked` with the hint `plays 69 s of 106 s` and skipped (the Spanish tab: `reproduce 69 s de 106 s`). If the TikTok app plays the episode whole, watch it there with the same account, then `--recheck` / **Look again** — the next list reads it fresh; if the app breaks at the same point too, nothing changes it until TikTok replaces the file.
- A short-served file is named after a download, instead of `download looks incomplete or wrong`. When the file TikTok serves is the whole episode by size — exactly what the list announced — but its header plays less, the episode is `failed-unavailable` with `TikTok serves this episode short: the whole file came (9676471 bytes, as listed) but it plays 70 s of 106 s — if the TikTok app plays it whole, watch it there, then --recheck looks again; if the app breaks at the same point, the episode is defective on TikTok's side and no retry changes it` (the extension names its checkbox instead; in Spanish, `TikTok sirve este episodio recortado: …`). The Python tool keeps the file as `<name> (short).mp4` (`(short 2)`, …) instead of `(incomplete)`; the extension saves nothing, as for every failed body. A file that is short for any other reason is still `(incomplete)` and retried. DramaFetch never rewrites a file's header to play past what it indexes.
- The extension's "did not download" report names the cause (`TikTok serves this episode short: the file is the whole episode by size but its header stops at 70 s of 106 s. Either a window for an episode this account has not unlocked, or a defective encode on TikTok's side — the list cannot tell: …`) and gains an `episodes_digest` per series: for every listed episode its number, access, hints, duration, `music.duration`, size, bitrate and the `IsPreview` / `PreviewType` marks — no URLs — so a wrong decision can be checked from the report alone. Its cause for a shorter file of a size the list did not announce states what was measured and both readings too (`the file plays 70 s where the list announces 106 s, and its size is none the list announced — a shorter file than listed: a window or a preview clip for an episode this account has not unlocked, or a defective encode on TikTok's side; …`), instead of calling it a preview for an episode the account has not unlocked.

## 1.2.0 — 2026-11-06

- The extension saves a report of the episodes a run did not download: `Downloads/DramaFetch/reports/<Series> - did not download <date time>.json`, written automatically at the end of a run with a failed episode (the setting **Save a report of the episodes that did not download**, on by default) or on **Save the report**. For each such episode — the failed ones, the ones a stop left `stopped`, the locked ones it skipped — its status, message and probable cause (a preview served for an episode the account has not unlocked, a cut transfer, DRM, a 429, …), every play URL considered with its HTTP status and sizes, every in-run re-discovery, and the list entry TikTok served to the session; plus one downloaded episode for comparison. Never a cookie, a token or a request header ([#81](https://github.com/brunocarbone98/projects/pull/81)).
- The version is shown next to the title of the DramaFetch tab and of the popup.

## 1.1.0 — 2026-11-06

- The episodes a run did not download are shown apart from the ones that completed, **Did not download (N)**, with **Retry the episodes that did not download (N)**: one job per series over exactly those episodes, the same as pasting the link and **Download selected** (the cooldown gate, the rest between jobs, a fresh list; locked episodes never asked for; a remembered DRM verdict skipped). Every past run with such episodes gets the same line and button in **Past runs** ([#80](https://github.com/brunocarbone98/projects/pull/80)).

## 1.0.0 — 2026-11-05

The first version the owner ran on a real Windows machine: the Python tool (`info`, `download`, `video`, `doctor`, `serve`) and the Chrome extension, with the audit fixes of [#79](https://github.com/brunocarbone98/projects/pull/79) — the full Chromium instead of the headless shell, consistent impersonated headers, no byte-offset resume, the video-only HEVC renditions left out, a captcha after the first list page treated as a stop, a private cookies copy for yt-dlp, the refused extractor arguments, one web server per port on Windows — and everything before it: whole series in batches, `<Series> - Episode NN.mp4` with the cover embedded, every file verified, the pacing floors and the 30-minute cooldown, paid episodes the account has unlocked and nothing more, DRM detected and never kept.
