# Changelog

One version for the whole of DramaFetch — the Python tool (`pyproject.toml`, `dramafetch --version`) and the Chrome extension (`extension/manifest.json`, shown in `chrome://extensions` and next to the title of the DramaFetch tab and the popup). Every change users can see ships with a new number: a new feature raises the middle number (1.2.0 → 1.3.0), a fix the last one (1.2.0 → 1.2.1). Dates are the day the version was finished.

## 1.6.0 — 2026-11-19

- **Your library.** The DramaFetch tab now shows your TikTok Bookmark — your profile → **Favorites** → **Drama** — as a library of cards: the cover, the title, `60 episodes · 1h 19m`, and what DramaFetch's own records say of each drama: **On disk · 60/60**, **Partly · 23/44**, **Not downloaded**, **Queued** while a job waits to download it and **Downloading · 12/30** while it does. Search by title, filter by status (**All**, **Not downloaded**, **Partly**, **On disk**, each with its count), sort (most recent first, title A–Z, most episodes), 60 cards at a time (**Show 60 more**): 946 dramas never slow the tab down. Two different dramas with the same title say **Same title as another favorite**. The library is kept on this computer — the dramas, their titles, episode counts and lengths, and TikTok's count; never a cover address or anything else TikTok signs — so the next time the tab opens it is there at once, without asking TikTok for the list (only the covers of the cards in view load, as long as their addresses are still signed: TikTok signs them for about two days, and an expired one is never asked for). A ticked card is framed in the tab's accent colour. Links at the top of the tab jump to **Download**, **Library**, **History** and **Settings** (every section stays on the page).
- **Open my library.** On your TikTok profile with **Favorites** → **Drama** shown, DramaFetch's toolbar button offers **Open my library · N dramas** in place of **Choose from your favorites**: the DramaFetch tab updates the library from that tab and shows it. Anywhere else the same button opens the tab on the library as it is kept — without asking TikTok for the list. **Update from TikTok** in the library does the same update, from the profile the library was read from only: while no tab of that profile shows your favorites list it is disabled, and a line names the profile and says to open its **Favorites** → **Drama** — a tab of another TikTok account never updates the library (**Open my library** on that account's profile makes its favorites the library).
- **The count is TikTok's, and it follows every removal.** The library shows how many dramas you still have in your Bookmark exactly as TikTok counts them (the list's own total) and when that was read: `Read from your TikTok tab (@you) · 2 min ago · TikTok counts 946 dramas`; when the library holds another number of dramas, a second line says so. An update reads the first page first: if TikTok's count and its first dramas are the library's, that one request is all (`No changes: TikTok counts 946 dramas.`); otherwise the whole list is read, one page at a time with the usual pause before each, and once TikTok's end is reached — or every drama TikTok counts has come — the library becomes that list. An update that stops before the end — TikTok refusing a page, **Stop**, the TikTok tab closed or logged out, TikTok sending no more, an empty first page — never shrinks the library kept: it keeps its dramas, their order and the removals, takes only TikTok's count and the entries of the dramas it read (so a drama that got new episodes says **Partly**; your own profile's list only), and the tab says the library was not updated; the very first read, while there is no library yet, keeps what it read. The library's profile is the one whose **Favorites** → **Drama** page made the request DramaFetch reads the list with, never the page that tab shows later. TikTok's whole list counting none empties the library: you have no favorites left. That shortcut holds for 24 hours after the whole list was last read: a drama that got new episodes changes neither TikTok's count nor the first page, so after a day the whole list is read again and such a drama says **Partly**. After every **Remove from Favorites** the count drops to TikTok's new total. Dramas removed directly on TikTok — in the app or the website — cannot be seen without asking TikTok: press **Update from TikTok**, and the list and the count are up to date again.
- **Download selected dramas.** Tick dramas (or **Select all shown**) and press **Download selected dramas**: ONE job downloads them one series after the other, exactly as **Download all** does with their ids in the box — the same engine, files, names, quality, checks, embedded covers, pauses, cooldown and report. While an update reads your whole list, the library refills page by page: pressed then, it takes the ticked dramas read so far — what the bar counts —, and the others keep their ticks for another press. The box is not touched; **Add selected to the box** still puts them there. **See episodes** lists a drama's episodes (**Load list**); **Open on TikTok** opens it in a normal tab.
- **Remove from Favorites** (in Spanish **Quitar de Bookmark**; the owner's request of 2026-11-19), on a drama DramaFetch's records show complete on disk — against an episode count read from TikTok in the last 24 hours (the whole list read since, or a download that found the drama complete since; otherwise nothing is asked of TikTok and the tab says to press **Update from TikTok** first). A confirmation first shows what the records say — `60 of 60 episodes on disk`, that DramaFetch downloaded and checked each one, when it was found complete, and `Cover included in every episode` only when every episode's record says so. Confirmed, DramaFetch opens the drama in a muted background tab, presses TikTok's own Bookmark button there ONCE — on that drama's own page only: a page TikTok sends the tab to instead is never read or pressed; and only when Chrome draws it yellow (saved) by the checks DramaFetch makes — the colour Chrome computes, never an attribute alone, on an element laid out, visible, not scaled, sized or clipped to nothing and not transparent: a yellow icon the page hides in one of those ways never counts; one hidden another way (clipped, off-screen, covered) is not detected, and on a button that is off the one press would add the drama back (DramaFetch then reports that TikTok did not confirm the removal) —, waits for it to turn off and for TikTok's answer to the page's request, reloads the page to check that TikTok kept it off, and closes the tab. When the drama's page already shows the Bookmark as off, nothing is pressed and nothing changes (that is no proof the drama left your list): if you removed it on TikTok yourself, press **Update from TikTok**. The card says **Removed from your Favorites** at once and leaves every filter count; with your profile's **Favorites** → **Drama** open in a tab, one request reads TikTok's new count (and if the drama is still on that first page, TikTok did not keep the change after all); without it, the count is the last one minus one, marked not confirmed. DramaFetch never sends TikTok's request itself — the page does, as when you click — but its click is a synthetic one: TikTok could ignore it or count it as automation. Then DramaFetch says TikTok did not keep the change, never presses twice, starts nothing that waits behind it, and you remove the drama yourself (**Open on TikTok**, then its Bookmark). To undo a removal, press Bookmark again on TikTok. A refusal by TikTok while removing (HTTP 429 or 403 on the Bookmark's request — also when it comes after you pressed **Stop** —, HTTP 429 on the drama page's own episode list, a captcha) is a stop with the 30-minute cooldown, like any refusal; TikTok's login page stops it too.
- The right-click **Download this favorite drama** costs what it cost in 1.5.0 once a library is kept: the part of your favorites list a right-click read is remembered for that tab, so the next right-click on a card it reaches needs no request. When two of your favorites share the right-clicked drama's title and the library lacks one of them (favorited since, or removed and bookmarked again), it joins the library — on top, as TikTok lists the newest first; a removed one is no longer marked removed — and the library shows every drama of that title for you to pick from; nothing leaves a library that holds your whole list (one that holds only part of it, a first read that stopped early, takes a reading at least as long from the list's top in its place). A right-click's reading kept for a tab goes into the library only while the library has learned nothing since that reading (no update, count or removal since); otherwise the list is read again, so a drama you removed never comes back and the count stays TikTok's. A right-click in a TikTok tab of another account than the library's never changes the library: when that account's favorites hold several dramas of the title, the tab says to open the one you want on TikTok and use **Download this series**.
- Downloads are unchanged: the library only puts series ids into the existing engine. No new permission.
- To update, replace the files in the SAME folder and press the reload arrow on DramaFetch's card in `chrome://extensions` while the DramaFetch tab shows **idle**, then press F5 on your TikTok profile tab and open **Favorites** → **Drama** again.
- The Python tool is unchanged and carries the same version number.

## 1.5.0 — 2026-11-15

- **Download from your TikTok favorites.** On your TikTok profile, open **Favorites** → **Drama**. Then either:
  - right-click a drama there — its title or its cover — and choose **Download this favorite drama** (in a Spanish Chrome, **Descargar este drama favorito**; DramaFetch's icon is next to it): the DramaFetch tab opens, or comes to the front, finds that drama in your favorites list and lists its episodes, exactly as when you paste its link. No more opening the drama and coming back: the entries of that list are buttons, not links, so until now the right-click had nothing to offer there. When two of your favorites bear that title (they may share the cover too), DramaFetch never guesses which one you meant: it lists neither and shows both in **Your favorite dramas**, with their episodes and length, for you to tick the one you right-clicked — and when the drama it finds is not where the card sits (favorites added elsewhere since your profile loaded move every card), it first reads a page further, so that the other one comes into view too. After adding favorites elsewhere (on your phone, say), press F5 on your profile before right-clicking: a page further covers most such moves, not all. A right-click that was not on a drama lists nothing, and the tab says so — right-click the drama's title or its cover, or use **Choose from your favorites**; in a TikTok tab that was open before DramaFetch was loaded or updated, the tab says to press F5 on your profile first. The item shows on `www.tiktok.com` profile pages, where DramaFetch's right-click script runs;
  - or click DramaFetch's toolbar button → **Choose from your favorites** (**Elegir de tus favoritos**): the DramaFetch tab lists every drama of that list — title, episodes and length, and **on disk** or **partly** when DramaFetch already saved all or some of its episodes — with a filter box and **Select all shown**. Tick the ones you want and press **Add selected to the box**: each joins the box as a `# <title>` line above its series id (two dramas with the same title stay two lines), and **Download all** downloads them, one series after the other. The panel itself downloads nothing. Your ticks stay when the list is shown again, and a right-click's own reading of the list never wipes the panel — except when it finds two favorites of the card's title: then the panel shows the part of the list that reading went through, filtered to that title (a ticked drama outside it shows again, still ticked, once **Choose from your favorites** lists the whole list).
- Downloads are unchanged: the same engine, names, quality, checks, embedded cover, pauses and 30-minute cooldown as a pasted link. Reading your favorites is paced like an episode list — one page at a time (19 dramas each), 0.8–1.6 s before every page, the rest between jobs before it, **Stop** between two pages — so 946 favorites take about 50 small requests and a minute or two; a refusal by TikTok stops it and starts the cooldown, like any list, a login page in your TikTok tab stops it too, and if TikTok stops sending the list before its end, the tab says so instead of passing a shorter list off as complete.
- How it knows the list: when your profile shows **Favorites** → **Drama**, the extension notes the address of the page's own request for the list's first page (its address and status only, kept in Chrome's memory until the tab or Chrome closes — never saved to disk, never in a report; the later pages your profile loads as you scroll never replace it), and reads the list from inside your TikTok tab: the first page with that same request, replayed unchanged, and each later page with that request with only its page cursor changed, as DramaFetch already does for a series' later episode-list pages. Whether TikTok accepts those later pages of this list could not be tried before release: if it answers one empty or with nothing new, the tab says TikTok stopped sending the list (no cooldown, nothing downloaded). If the button does not show, or the tab says DramaFetch has not seen your favorites list, open **Favorites** → **Drama** again on your profile (or press F5 there and open **Drama** again). A small script on TikTok's pages notes which drama card you right-clicked — its name and position, nothing else — and changes nothing in the page. No new permission.
- Removing a drama from your favorites is not part of DramaFetch: do it on TikTok.
- To update, replace the files in the SAME folder and press the reload arrow on DramaFetch's card in `chrome://extensions` while the DramaFetch tab shows **idle** — a restart of Chrome does not do it: until the arrow is pressed, Chrome keeps running 1.4.0's background code, and neither the new right-click item nor the button appears. Then reload your TikTok profile tab (F5), so that it gets the right-click script.
- The Python tool is unchanged and carries the same version number.

## 1.4.0 — 2026-11-14

- **Download this drama** from the right-click menu. Right-click a link to a TikTok short-drama series — in TikTok's own lists of dramas, or on any other page — and choose **Download this drama** (in a Spanish Chrome, **Descargar este drama**): the DramaFetch tab opens, or comes to the front if it is already open, and lists the series' episodes, waiting its turn behind a job that is running. There is no need to open the series first and copy its address. On the page of a series itself, a right-click on an empty part of the page — not on a link, the video, a picture or a text box, and with no text selected — offers **Download this page's drama** (**Descargar el drama de esta página**). Nothing is downloaded until a download button is pressed in the tab. The item shows on a list's entries only when they are links to the series, which could not be checked against TikTok itself: where it does not show, open the series and use the popup, as before.
- A series handed over — by the right-click or by the popup's **Download this series** — joins the box on a line of its own instead of replacing what is there, so a batch typed for **Download all** stays and a series already in the box is not added twice; an address that names no series leaves the box as it is, and the tab says why it lists nothing.
- A series handed over is no longer lost. When the open DramaFetch tab was not running — Chrome restored it after a restart without loading it yet, or it was discarded (`chrome://discards`, a tab-suspending extension) — or it was a read-only one left behind by a closed DramaFetch tab, the tab came to the front with nothing listed. Now the tab that runs DramaFetch takes the series and comes to the front, and when no tab can take it, the open DramaFetch tab reloads with the series and lists it.
- The extension declares the `contextMenus` permission for it (the README's permissions table says why): of what Chrome passes with a click (the link's and the page's addresses, any selected text, the tab), DramaFetch reads only the link's address, or the page's, and keeps nothing. To update, replace the files in the SAME folder and press the reload arrow on DramaFetch's card in `chrome://extensions`, as always — a restart of Chrome does not do it: until the arrow is pressed, Chrome keeps running 1.3.1's background code, and the right-click items do not appear.
- The Python tool is unchanged and carries the same version number.

## 1.3.1 — 2026-11-12

- No limit on how many series the extension remembers. Its memory of what is already on disk — one small record per episode, what makes a second run skip everything it has — lives in Chrome's storage for the extension, which Chrome holds to 10 MB unless the extension asks otherwise. At about 350–400 bytes per episode that was full near 27 000 episodes (some 450 series of 60): from then on a run died at its first episode with Chrome's raw `Resource::kQuotaBytes quota exceeded` and recorded nothing. The extension now declares `unlimitedStorage` (the README's permissions table says why): the same data in the same place, no new warning from Chrome, and everything already stored stays. To update, replace the files in the SAME folder and press the reload arrow on DramaFetch's card in `chrome://extensions`, as always — a second folder would be a second extension with an empty memory.
- A full disk stops a run cleanly. If Chrome still refuses to store the progress — the disk that holds your Chrome profile is full or failing — the episode just saved keeps its row, nothing more is asked of TikTok (no job, no listing, no thumbnail: the tab's buttons stay disabled until it is reloaded), the rest of the series is `stopped: the progress could not be saved: …` under **Did not download** with its report, the jobs waiting behind it do not start, and the tab says what to do: `DramaFetch stopped: … Free some space, restart Chrome and run again: what is already saved is skipped.` A 30-minute cooldown that cannot be stored is in force all the same until Chrome closes or the extension is reloaded — a reload of the tab keeps it, and the open tab writes it again within 15 s once Chrome takes writes — and while a cooldown is in force the message names its end: restart Chrome or reload DramaFetch only after it (what Chrome accepts after a refused write may not survive its restart). Before, the waiting jobs started anyway and a 429 met at that moment started no cooldown.
- Long batches stay light. In a batch of hundreds of series the tab used to keep every episode's row, list entry and download trace until the end — gigabytes and about a second per table update by some 900 series —, its report of what did not download could pass 512 MB and fail to save, the run's entry in **Past runs** pushed every earlier run out (and at Chrome's old quota wiped them), and a table of more than about 124 000 rows broke the end of the job. Now the progress table keeps the most recent rows (about 2 000) and says so, a finished series' list entries and traces are let go of once the report has what it needs, the report keeps the list entry of at most three locked episodes per series (all of them still described), and every run is held to its share of **Past runs** (about 51 KB), so the last 20 runs stay together: a larger run is kept there in a compact form — its episodes that did not download, so its retry button works —, and a batch of more than about 200 series (about 120–190 when a stop left most of them `not started`) keeps its series with an episode to retry first, then as many others as fit, and says how many more it had. What is downloaded, and how, does not change.
- The README names the other full disk too: `could not save <file>.mp4: FILE_NO_SPACE` means the disk of your download folder is full, and what to do about it — and gains **Hundreds of series**: about 50 series per batch, never clearing Chrome's download list during the project, and what a long download list costs Chrome itself.
- The Python tool is unchanged — it keeps its memory in a file next to the videos — and carries the same version number.

## 1.3.0 — 2026-11-07

- Free series with conditions are read right. A series TikTok marks `isLimitedFree: true` — free, with conditions the field does not name — listed every episode as `locked` with hints such as `isFree=false; IsPreview=True; PreviewType=4`, so **Download all available** downloaded nothing and the Python tool skipped everything: `IsFreeIntro` ("is this the free intro teaser"), `IsPreview` and `PreviewType` say nothing about what your session may play — the owner's real list of 2026-11-06 had them on fully served episodes too — and they no longer count as locks or prices. Such a series now lists as `free` and downloads with one click; its hint `isLimitedFree=True` appears only next to a price (`unlockPrice`), where it says why a sold episode is free.
- A short header is told before any request. Some episodes come as a file that is the whole episode by size but whose header plays only part of it — about 70 s of a 106 s episode — and the list gives it away: the episode's own sound (`music.duration`) is far shorter than the episode (`video.duration`). That can be a window for an episode your account has not unlocked, or a defective encode on TikTok's side — the owner's 7 episodes of 2026-11-06 broke at the same point in the TikTok app and in TikTok's web player: no sound past it, a broken picture when seeking past it — and the list cannot tell the two apart. Such an episode is listed `locked` with the hint `plays 69 s of 106 s` and skipped (the Spanish tab: `reproduce 69 s de 106 s`). If the TikTok app plays the episode whole, watch it there with the same account, then `--recheck` / **Look again** — the next list reads it fresh; if the app breaks at the same point too, nothing changes it until TikTok replaces the file.
- A short-served file is named after a download, instead of `download looks incomplete or wrong`. When the file TikTok serves is the whole episode by size — exactly what the list announced — but its header plays less, the episode is `failed-unavailable` with `TikTok serves this episode short: the whole file came (9676471 bytes, as listed) but it plays 70 s of 106 s — if the TikTok app plays it whole, watch it there, then --recheck looks again; if the app breaks at the same point, the episode is defective on TikTok's side and no retry changes it` (the extension names its checkbox instead; in Spanish, `TikTok sirve este episodio recortado: …`). The Python tool keeps the file as `<name> (short).mp4` (`(short 2)`, …) instead of `(incomplete)`; the extension saves nothing, as for every failed body. A file that is short for any other reason is still `(incomplete)` and retried. DramaFetch never rewrites a file's header to play past what it indexes.
- The extension's "did not download" report names the cause (`TikTok serves this episode short: the file is the whole episode by size but its header stops at 70 s of 106 s. Either a window for an episode this account has not unlocked, or a defective encode on TikTok's side — the list cannot tell: …`) and gains an `episodes_digest` per series: for every listed episode its number, access, hints, duration, `music.duration`, size, bitrate and the `IsPreview` / `PreviewType` marks — no URLs — so a wrong decision can be checked from the report alone. Its cause for a shorter file of a size the list did not announce states what was measured and both readings too (`the file plays 70 s where the list announces 106 s, and its size is none the list announced — a shorter file than listed: a window or a preview clip for an episode this account has not unlocked, or a defective encode on TikTok's side; …`), instead of calling it a preview for an episode the account has not unlocked.

## 1.2.0 — 2026-11-06

- The extension saves a report of the episodes a run did not download: `Downloads/DramaFetch/reports/<Series> - did not download <date time>.json`, written automatically at the end of a run with a failed episode (the setting **Save a report of the episodes that did not download**, on by default) or on **Save the report**. For each such episode — the failed ones, the ones a stop left `stopped`, the locked ones it skipped — its status, message and probable cause (a preview served for an episode the account has not unlocked, a cut transfer, DRM, a 429, …), every play URL considered with its HTTP status and sizes, every in-run re-discovery, and the list entry TikTok served to the session; plus one downloaded episode for comparison. Never a cookie, a token or a request header ([#81](https://github.com/brunocarbone98/projects/pull/81)).
- The version is shown next to the title of the DramaFetch tab and of the popup.

## 1.1.0 — 2026-11-06

- The episodes a run did not download are shown apart from the ones that completed, **Did not download (N)**, with **Retry the episodes that did not download (N)**: one job per series over exactly those episodes, the same as pasting the link and **Download selected** (the cooldown gate, the rest between jobs, a fresh list; locked episodes never asked for; a remembered DRM verdict skipped). Every past run with such episodes gets the same line and button in **Past runs** ([#80](https://github.com/brunocarbone98/projects/pull/80)).

## 1.0.0 — 2026-11-05

The first version the owner ran on a real Windows machine: the Python tool (`info`, `download`, `video`, `doctor`, `serve`) and the Chrome extension, with the audit fixes of [#79](https://github.com/brunocarbone98/projects/pull/79) — the full Chromium instead of the headless shell, consistent impersonated headers, no byte-offset resume, the video-only HEVC renditions left out, a captcha after the first list page treated as a stop, a private cookies copy for yt-dlp, the refused extractor arguments, one web server per port on Windows — and everything before it: whole series in batches, `<Series> - Episode NN.mp4` with the cover embedded, every file verified, the pacing floors and the 30-minute cooldown, paid episodes the account has unlocked and nothing more, DRM detected and never kept.
