# CLAUDE.md — DramaFetch

Rules for agents working in `DramaFetch/`. The repo-wide rules in `../AGENTS.md` and `../CLAUDE.md` (guardrails, branches, PRs) still apply; this file adds what is specific to this project. Read it before touching anything here.

## Scope — what this tool is and is not

- DramaFetch downloads TikTok short-drama episodes that the user's own account can already watch, a whole series at a time, for personal offline viewing. That is the whole product. The legal notice in `README.md` is part of the contract: keep it verbatim in the README and in `web/static/index.html`.
- Never implement anything that unlocks paid episodes, bypasses a paywall, DRM or access controls, fakes entitlement, rotates proxies or hides automation. The only two deliberate measures are a Chrome user agent without `Headless` (`static.chrome_user_agent`, used by the discovery and the browser engine alike) and curl_cffi's Chrome TLS impersonation (`impersonate="chrome"` in `static.py` and yt-dlp's `impersonate` in `downloader.py`), which is how yt-dlp normally talks to TikTok. Chromium runs with its default flags (`navigator.webdriver` stays true); when TikTok asks for a verification the user passes it with `--headful`. No proxies, no stealth plugins, nothing else. Locked episodes are listed with their hints and skipped; `--include-locked` only _tries_ them.
- Cookies are a key to the user's account: never print, log, dump, assert on or send cookie values anywhere but TikTok. Diagnostics (`doctor`, `--dump-raw`, error messages, job snapshots) may show cookie **names**, counts and ages only.
- Be polite to TikTok by design: one download at a time, randomized 4–9 s pauses between episodes, a 60–120 s rest every 10 downloads, 0.8 s between list pages, a full stop on HTTP 403, HTTP 429 or three failures in a row (see Pacing below). Never add parallelism.
- One small cover (thumbnail) request per episode in the browser engine: one `GET` of `Episode.cover_url` after its video and only then, outside the media budget (`MAX_COVER_GETS = 1`), never retried, never a second candidate; its failure only appends `; cover: <reason>` to a `done` result (a 429 there is a WARNING, not a stop). The yt-dlp engine delegates the fetch to yt-dlp's `writethumbnail`, which gets the cover just before the video, names it after the cover URL's extension (`.jpeg` for TikTok) and reports nothing when it fails. By default (`DownloadOptions.thumbnail = "embed"`, `--thumbnail`) the cover then goes INTO the MP4 as its cover art — the `covr` atom, written by mutagen in `thumbnails.embed_cover` — and no sidecar stays; `both` keeps the sidecar too, `file` only the sidecar, `none` makes no cover request at all. Never modify a downloaded video in place: embedding edits a copy (`<name>.embed.part`) that replaces the original atomically, and any failure deletes the copy, leaves the video byte for byte and keeps the cover as a file (the message says so; the status never changes). A skipped episode never fetches a missing cover.
- The cloud sandbox and CI cannot reach tiktok.com — never try. Everything network-facing is thin, injectable and tested against `tests/fixtures/` or `tests/integration/fake_tiktok.py`.
- The web UI never serves a path outside `--out`: `GET /api/files/…` streams only what a finished job row recorded, after resolving it inside `out_dir`, and answers a 404 that names no path to anything else. Binding `serve` to anything but loopback requires `--token` (or `DRAMAFETCH_TOKEN`; at least 8 cookie-safe characters), which every `/api/*` request must then carry as `Authorization: Bearer <token>` or the `dramafetch_session` cookie; the token value never appears in logs, messages or snapshots (`token: set` / `token: none`).

## Pacing

The anti-bot strategy is to behave like one person watching, and it lives in `engine.download_series` with its knobs in `models.DownloadOptions`:

- The defaults are deliberate and are a floor: 4–9 s between episodes (`delay_min_s`/`delay_max_s`), a 60–120 s rest every 10 network attempts (`rest_every`, `rest_min_s`/`rest_max_s`; a failed attempt counts, skips do not), a stop after 3 consecutive failures (`max_consecutive_failures`), at most 3 yt-dlp retries (`downloader.MAX_RETRIES`) with `sleep_interval_requests: 1`, at most 4 media requests per episode in the browser engine (`downloader_browser.MAX_GETS_PER_EPISODE`) plus at most one cover request (`MAX_COVER_GETS`). Never lower them in code, never make the code itself go below them, never make a pause conditional on "it worked last time". The existing flags accept lower values only so that tests against the fake server run fast; do not add further ways to go below the defaults. Users may raise them (`--pace human`, `--rest-every 5`, …); the only way to make a run lighter is fewer requests (`--engine browser`), never faster ones.
- Never parallelise: one download at a time in the engine, one job at a time in `web/jobs.py`, one browser context in the browser engine. No proxies, no rotation, no second instance.
- `DownloadStatus.FAILED_BLOCKED` (HTTP 403 / forbidden / access denied from yt-dlp; a captcha page met by the browser engine's in-session list refresh) and `FAILED_RATE_LIMITED` (HTTP 429) stop the run, like `FAILED_LOGIN`: the remaining episodes get the same status with `stopped: …` and no request is made (`engine._STOP_STATUSES`); `exit_code` returns 5 for both. Do not retry, wait-and-knock or switch engines automatically after one — the user waits 30–60 minutes and resumes with the manifest. Keep `downloader.classify_error` mapping 403 wordings to `FAILED_BLOCKED` and `\b429\b` to `FAILED_RATE_LIMITED`.
- Every pause goes through `on_pause(kind, seconds)` then the injectable `sleep`; skips (manifest, locked, existing file, dry run) never pause and never count. Tests use a fake `sleep` and a fixed `rng` — a test that really sleeps is a bug.

## Architecture (`src/dramafetch/`)

| Module | Role |
| --- | --- |
| `models.py` | Dataclasses (`SeriesRef`, `VideoRef`, `Episode`, `Series`, options, `DownloadStatus`, `DownloadResult`) and the `Discovery` / `Downloader` protocols — pure data, shared by everything; `THUMBNAIL_MODES` (`embed` `both` `file` `none`) and `DownloadOptions.thumbnail` with its `thumbnails` / `embed_cover` / `keep_cover_file` properties |
| `errors.py` | Exception hierarchy; each class maps to one CLI exit code — except `ThumbnailError`, which never escapes an engine (a cover that cannot be embedded is kept as a file and reported in the message) |
| `urls.py` | Parse pasted text into `SeriesRef` / `VideoRef`, build page URLs; its docstring holds the verified URL facts |
| `catalog.py` | Pure functions over TikTok's `item_list` / `detail` payloads: find lists, lock hints, episodes, merge, warnings, play URLs, the cover URL (`cover_url_of`: `video.originCover` → `cover` → `dynamicCover`, each a string, a list or a `UrlList` dict) |
| `discovery/` | `browser.py` (Playwright: open the series page, capture `/api/drama/episode/item_list/`, paginate; `discover_in_page` runs the same capture in a page of a context the browser engine already holds), `static.py` (embedded page JSON), `cookies.py` (Netscape `cookies.txt` → Playwright cookies, names-only report, malformed lines by line number), `__init__.py` (`choose_discovery`: `auto` = static, then browser) |
| `manifest.py` | `dramafetch.json` per series directory: resumable runs, `safe_filename`, the series directory name and the episode file name: `episode_stem(episode, options)` expands `DownloadOptions.name_format` — placeholders `{series}` `{number}` `{n}` `{title}` `{id}` (`NAME_PLACEHOLDERS`), replaced one by one, never `str.format`; `validate_name_format` refuses anything else, an unmatched brace or a format that does not tell episodes apart — default `<series> - Episode NN` (`models.DEFAULT_NAME_FORMAT`), whole stem through `safe_filename(…, 150)` |
| `downloader.py` | `YtDlpDownloader`: builds yt-dlp options (`%`-escaped output template, retries capped at `MAX_RETRIES`, `writethumbnail` when `DownloadOptions.thumbnails` — every mode but `none`: the cover lands next to the video as `<stem>.<the cover URL's extension>`, `.jpeg` for TikTok, fetched by yt-dlp just before the video; no postprocessor, no yt-dlp embedding), then `_finish_cover(video, options)` after a DONE: reads the sidecar (`WRITTEN_COVER_SUFFIXES` = `COVER_SUFFIXES` + `.image`, renamed after its bytes; over `MAX_COVER_BYTES` → deleted), embeds it with `thumbnails.embed_cover` and deletes it (`embed`), keeps it too (`both`) or only (`file`), and appends ` + cover embedded` / ` + cover embedded + file` / ` + cover file` or `; cover: not available` / `; cover: webp cannot be embedded; file kept` / `; cover: could not embed (<reason>); file kept` / `; cover: too large, not kept` / `; cover: not a JPEG, PNG or WEBP image; file kept` / `; cover: <OS error>; file kept` to the message, never changing the status; classifies errors (403 → `FAILED_BLOCKED` with `BLOCKED_MESSAGE`, 429 → `FAILED_RATE_LIMITED`), refuses a cookies file with malformed lines (yt-dlp would print them), never raises per episode; its skip-rule helpers are shared with the browser engine and `existing_episode_file(out_dir, episode, options)` counts `VIDEO_SUFFIXES` (`.mp4 .m4v .mov .mkv .webm`) only and the whole stem only (`Path.stem ==`, never a prefix) — a `.jpeg`/`.jpg` sidecar is never the video, nor is another episode's `Ep 1.5.mp4` ever `Ep 1`'s |
| `downloader_browser.py` | `BrowserDownloader`: the `--engine browser` downloader — one lazily launched Chromium of its own (default flags, Chrome UA, the cookies file; set up like the discovery's, not shared with it) and one context for the whole run; fetches the play URLs the `item_list` payload already carries (`catalog.play_url_candidates`, expiry from `catalog.url_expiry`, `Referer: <base_url>/`), one `GET` at a time and at most `MAX_GETS_PER_EPISODE` (4) per episode; 403/404/410 or a non-video body → next URL → at most one in-session refresh of the episode list per episode (`PlaywrightDiscovery.discover_in_page`, cached per run so a long series refreshes once; an episode the fresh list carries without a play URL, or not at all, never costs another page load) → `FAILED_UNAVAILABLE`; any other HTTP status → `FAILED` at once (no next URL, no refresh); 429 → `FAILED_RATE_LIMITED`; a captcha page during the refresh → `FAILED_BLOCKED`; writes `.part` then renames; after a DONE, and only then, one cover `GET` (`Episode.cover_url`, `MAX_COVER_GETS = 1`, outside `MAX_GETS_PER_EPISODE`, no pause before it; accepted at ≥ `MIN_IMAGE_BYTES` and ≤ `MAX_COVER_BYTES` with an `image/*` type or JPEG/PNG/WEBP magic — `thumbnails.image_kind`, the bytes first — then `_keep_cover`: embedded into the MP4 with `thumbnails.embed_cover` and/or written atomically as `<stem>.jpg|png|webp` per `DownloadOptions.thumbnail`, a WEBP or a failed embed saved as the file instead: ` + cover embedded` / ` + cover embedded + file` / ` + cover file` / `; cover: webp cannot be embedded; saved as file` / `; cover: could not embed (<reason>); saved as file` / `; cover: too large, not kept`) whose failure only appends `; cover: <reason>` to the message (a 429 there is a WARNING, not a stop); a failed launch is attempted once and never retried: every later episode fails with the same cached message until the 3-failure stop ends the run; `close()` at the end of the run; messages carry host names only |
| `thumbnails.py` | The episode cover, shared by both engines and the web: `image_kind(data, content_type)` → `jpeg` / `png` / `webp` / None (the bytes first, then the content type), `extension_for`, `mime_type_for`, `image_problem`, `format_size`; `cover_sidecar(video)` (the first `<stem>.jpg|.jpeg|.png|.webp` next to it — `COVER_SUFFIXES`); `embed_cover(video, image)`: the `covr` atom through mutagen (imported lazily, so everything else runs without it), JPEG or PNG only (a WEBP cannot live there), `.mp4`/`.m4v`/`.mov` only (`EMBEDDABLE_SUFFIXES`), at most `MAX_COVER_BYTES` (5 MiB) — copies the video to `<name>.embed.part` (`EMBED_SUFFIX`), tags the copy, `os.replace`s it over the original; any failure deletes the copy, leaves the video byte for byte and raises `ThumbnailError` with a printable reason (`mutagen is not installed: pip install mutagen`, `webp cannot be embedded`, …); `extract_cover(video)` → `(bytes, "image/jpeg" \| "image/png")` or None, never raises, the bytes decide the type, nothing over `MAX_COVER_BYTES`; `has_embedded_cover` |
| `engine.py` | The seam both front ends use: `resolve`, `select_episodes`, `download_series` (pacing, rests, early stops, `on_pause`; hands the downloader `options` with `out_dir` = the series directory and `series_name` = the series' display name), `make_downloader` (engine → downloader, closes it at the end), `validate_pacing`, `validate_naming`, `validate_thumbnail` (all three before the series directory is created), `summarize`, `exit_code` |
| `cli.py` | argparse front end: `info`, `download`, `video`, `doctor`, `serve`; `--thumbnail {embed,both,file,none}` on `download`, `video` and `serve` (default `embed`; the help names what each mode does); `doctor` prints the `doctor_checks` facts, then a `mutagen` line (`✓ mutagen: <version> (covers are embedded into the MP4)` / `✗ mutagen: not importable — covers are saved as files only (pip install mutagen)`) and the `pace` line — nine lines; `doctor_as_dicts` feeds the web UI with the seven environment checks only |
| `web/` | stdlib `http.server` UI: `server.py` (routes, limits, `run_server`; the `Host` guard — `host_header_allowed`: the bound host or localhost, and for a wildcard bind any IP literal but no other host name; the access token — `--token` / `DRAMAFETCH_TOKEN`, required off loopback, checked with `hmac.compare_digest` — the Bearer token or the first `dramafetch_session` cookie, two candidates per request at most — on every request but `GET /` and `POST /api/session`, which turns the right token into the `dramafetch_session` cookie; the files endpoint `GET /api/files/<job>/<n>[/cover]`, which streams only a `done` row's path once it resolves inside `out_dir`, 64 KiB at a time — `/cover` is the `<stem>.jpg|.jpeg|.png|.webp` sidecar when one exists (`thumbnails.cover_sidecar`), else the cover embedded in that video (`thumbnails.extract_cover`, called only after the video passed the same confinement check; sent from memory as `image/jpeg`/`image/png` with `Content-Length`, named `<stem>.jpg|.png`, refused over `MAX_COVER_BYTES`) — and answers one path-free 404 to everything else), `jobs.py` (`JobManager`: one job at a time, polled snapshots whose rows carry `path`, `file_name` and `thumbnail` — "a cover is available", as a sidecar or embedded (`has_cover`), computed once when the row is recorded, never on a poll), `static/index.html` (vanilla JS, no CDN: covers, **Download all free**, **Save video** / **Cover** links — the embedded or the saved cover — the token form shown on a 401 of kind `auth`) |

Dependencies flow downwards: `cli` / `web` → `engine` → `discovery` / `downloader` / `downloader_browser` / `manifest` / `catalog` → `thumbnails` (imports `errors` only, and mutagen lazily; `web` uses it too) → `models` / `urls` / `errors`. `engine` imports `downloader_browser` lazily (`make_downloader`), so the default engine never loads Playwright. `web` imports `engine` and `cli` lazily inside handlers so the package loads without Playwright or yt-dlp; `cli` imports `web.server` lazily for `serve` (the `--token`/`--host` checks and `run_server`).

## Conventions

- English everywhere; conventional commits (`feat(dramafetch): …`, `fix(dramafetch): …`).
- Type hints on everything and `mypy --strict` green; `typing.Any` only for raw TikTok JSON. No `# type: ignore` without a reason in the comment.
- Parsing is pure functions over payloads, covered by the fixtures in `tests/fixtures/` (two consecutive `item_list` pages with a trailer, a duplicate, a locked episode and an item from another series). Keep fixtures realistic when extending them.
- The network layer is thin and injectable: the `Discovery` / `Downloader` protocols, the `fetch` / `playwright_factory` / `ydl_factory` constructor hooks, `DiscoveryOptions.base_url` for the fake server. Tests inject fakes; no test opens a socket to the internet.
- No new runtime dependencies beyond `yt-dlp`, `playwright` and `mutagen` (pure Python; it writes the cover into the MP4 — `curl_cffi` is an optional extra). Stdlib only under `web/`; no CDN or external resource in `index.html`.
- Never weaken `pyproject.toml` (ruff rules, mypy strict, pytest markers/addopts) to get green; never skip or quarantine a test.
- Error messages are safe to print: no cookies, no tokens, no tracebacks in user-facing text (`logging.debug` the detail). Web responses never echo request bodies.

## Definition of done

1. `ruff check`, `ruff format --check`, `mypy` and `pytest` are green; `pytest -m integration` too when a Chromium is available. Report the real output.
2. Anything users see — flags, exit codes, output layout, statuses, API routes, pacing defaults — is reflected in `README.md` (flags table, exit codes, "Pacing and TikTok's protections"); a new or moved module appears in the table above.
3. No cookie value anywhere, no bypass of any kind, no parallel downloads, no new dependencies.
4. Fixtures and `tests/integration/fake_tiktok.py` were updated whenever TikTok's payload shape changed.

## Where the TikTok facts live and how to update them

The verified facts — the series URL shape, "the long number is the series id (`dramaID`)", `/api/drama/episode/item_list/`, `/api/drama/detail/`, "a logged-in session is required", yt-dlp issue #17725 — are written down in `urls.py` (module docstring) and `README.md` → "How it works", and encoded in `catalog.py` (field names, lock heuristics) and `discovery/browser.py` (URL substrings, pagination parameters). When TikTok changes something:

1. On a real machine run `dramafetch info URL --cookies cookies.txt --strategy browser --dump-raw raw/`; it writes `item_list_<n>.json`, `detail.json` and `page_url.txt` (never cookies). With `--strategy auto` or `static` the embedded page JSON lands in `hydration_<n>.json` instead, and `item_list_<n>.json`/`detail.json` appear only if the browser had to run.
2. Compare them with `tests/fixtures/item_list_page*.json`; update the fixtures to the new shape (anonymise ids) and adjust `catalog.py` / `discovery/` until `pytest` passes again.
3. Update the facts in `urls.py`, `README.md` and this file in the same PR, with the date they were verified.
