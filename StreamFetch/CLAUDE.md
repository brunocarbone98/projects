# CLAUDE.md — StreamFetch

Rules for agents working in `StreamFetch/`. The repo-wide rules in `../AGENTS.md` and `../CLAUDE.md` (guardrails, branches, PRs) still apply; this file adds what is specific to this project. Read it before touching anything here. StreamFetch is a sibling of `../DramaFetch/extension/`: same engineering rules, same quality bar, same legal posture — and no shared code. Copy and adapt DramaFetch's patterns; never import across projects.

## Scope — what this tool is and is not

- StreamFetch for Chrome is a Manifest V3 extension (Windows first, installed with **Load unpacked**) that saves videos from **Dailymotion**, **Bilibili.tv** (Bstation, `biliintl.com`: Bilibili's international site, a different service) and **Bilibili** (`bilibili.com`) as progressive MP4 files, for personal offline viewing — only what the user's OWN logged-in Chrome session can already play there. That is the whole product. The legal notice in `README.md` is part of the contract: keep it verbatim in the README, in `extension/_locales/en/messages.json` (`legalNotice`; `es` carries a faithful translation) and the footer of `extension/src/app/app.html` (`#legal-notice`, localized); `extension/tests/locales.test.js` compares the English text with the README.
- Never: decrypt or strip DRM (an `EXT-X-KEY` whose METHOD is not `NONE`, or `encv` / `enca` / `pssh` boxes, is refused before anything is saved — `key_protected`, `encrypted`); bypass a paywall, premium, supporter-only or trial restriction, a geo-restriction, an age gate, a login or any access control; compute, forge or replay a site's request signature or risk-control parameter (Bilibili's playurl answer is the one the page itself embeds; Bilibili.tv's playurl is requested with the ids of the pasted link and nothing else); spoof a fingerprint or user agent; use proxies, VPN tricks or IP rotation; patch, wrap or inject into a site's page (no content script, no `scripting`). The extension reads the page or JSON the site serves to the user's browser and fetches the media URLs that document offers, with the browser's own cookies (`credentials: "include"`).
- The ONLY header changes are on the extension's own media requests: `Referer` set to the site's origin (`https://www.dailymotion.com/`, `https://www.bilibili.com/`, `https://www.bilibili.tv/`) and `Origin` removed — what the sites' own players send — through ONE declarativeNetRequest session rule whose initiator is the extension itself (`app/downloader.js` `refererRule` / `applyRefererRule`, `REFERER_RULE_ID`; `requestDomains` = `MEDIA_DOMAINS[site]` in production, a `urlFilter` on the fake base in test mode). Because the rule matches whole domains, the extension's own Dailymotion metadata and playlist requests (`dailymotion.com`, like its media) and Bilibili.tv API requests (A.1 wants the header) carry it too; the README says so. Never widen it to another domain or initiator.
- A trial clip, a supporter-only preview, an encrypted file or a file shorter than the site's duration is NEVER saved as the video (`trial_only` whenever `试看` appears in Bilibili's `accept_description`; `supporter_only`; `verify_failed`). No fragmented or unfinished fallback file is saved in 1.0.
- Cookies, tokens and `Authorization` values are never read, logged, stored, asserted on or exported; the report strips the query string of every URL it holds (both sites sign media URLs there) and never contains a request header.
- Be polite by design (Pacing below): one video at a time, one request at a time, jittered pauses, bounded retries, a full stop and a 30-minute cooldown after a refusal. Never parallelise; never add a way to skip the cooldown or go below a floor.
- The cloud sandbox and CI cannot reach dailymotion.com, bilibili.com or bilibili.tv — never try. Every site fact comes from yt-dlp's extractors (below) and every behaviour is tested against `tests/fake_sites.py`.

## The owner's acceptance criteria

What the owner asked StreamFetch to do (2026-11-08, Addendum A, and the directive of 2026-11-11: "download everything well, exactly the way DramaFetch does — complete videos, high audio and video quality; DramaFetch works perfectly, I expect the same level or better from StreamFetch"). Every change keeps all eight true, and `code-reviewer` and `test-runner` judge a change against them — inside the Scope above, never against it:

1. **Several links at once.** One link per line in `#links`, up to `urls.MAX_ITEMS` (100); duplicates dropped by canonical key (the same Bilibili.tv video with another language segment or `bstar_from`, the same Bilibili video with other share parameters, a `b23.tv` link re-keyed after its redirect); everything else refused with a reason before anything starts. Resolved and downloaded strictly one item after the other (`app/engine.js` `runBatch`). Proven by `tests/urls.test.js`, `tests/engine.test.js` and `tests/test_e2e_batch.py`.
2. **The three sites, in the shapes users paste.** Dailymotion (`/video/<xid>[_slug]`, `dai.ly`, embeds, the geo player; a `?playlist=` on a video link ignored with the hint `playlist ignored: only this video is downloaded`), Bilibili.tv (`[www.]bilibili.tv` / `biliintl.com`, optional language segment, `video/<aid>`, `play/<season>/<ep>`, `play|media/<season>`; every query parameter ignored; ids are STRINGS end to end — a 16-digit aid never goes through `Number`), Bilibili (`BV…` / `av…`, `m.`, bare, no scheme, `?p=N` the only meaningful parameter, `b23.tv` followed). Tests never carry the owner's ids: they use yt-dlp's public example ids (from its extractors' own tests) and invented ids of the real shapes.
3. **Complete files with audio and video.** Every saved file is a progressive MP4 (`moov` before `mdat`, no `moof`) with one video track and one audio track (unless the source has none), every track's duration within max(3 s, 5 %) of the site's (`downloader.DURATION_TOLERANCE_S` / `_RATIO`) and no hole inside a track (`downloader.mediaGap`: a step between two samples longer than `GAP_FACTOR` typical ones and `GAP_TOLERANCE_S`, or `DAMAGED_GAP_FACTOR` once the MPEG-TS demuxer met damaged data), checked by `mp4.probe` before `chrome.downloads` sees it; a segment served as an error page or empty (`tsSegmentProblem` / `mp4SegmentProblem`) is retried, never demuxed or appended; the e2e suite proves, for every media path (TS-HLS, fMP4-HLS, Bilibili DASH, Bilibili.tv progressive and fragmented MP4), that the saved video stream is framemd5-equal to the source and the audio equal to what the writer was given.
4. **The highest quality the session gets.** Defaults `quality: "best"` (the highest resolution served; `1080` / `720` / `480` are optional caps) and `codec: "compatible"`; the codec preference applies only among streams of the chosen height (`compatible`: avc → hevc → av1; `best`: highest bandwidth) — the resolution is never lowered to get H.264. Audio: `compatible` the highest-bandwidth AAC, `best` FLAC, then Dolby, then AAC. A per-row selector (`select.quality-select`) overrides the policy; premium-only qualities appear as disabled options. Nothing is re-encoded.
5. **Cover and title embedded.** `remux.writeProgressiveMp4(…, { meta })` writes `moov/udta/meta/ilst` with `©nam` (UTF-8) and `covr` (JPEG 13 / PNG 14, at most `remux.MAX_COVER_BYTES`, 5 MiB); the setting `cover: "embed"` (default) or `"none"` (title only, no cover request). One cover request per file after its media, never retried, outside the media budget, a 429/403 on it never a stop; WebP and others converted to JPEG (`OffscreenCanvas`, quality `COVER_JPEG_QUALITY` 0.92); a failure still saves the video and ends a `done` row's message with `; cover: <reason>`. Samples untouched (framemd5 proof in `tests/test_e2e_covers.py`).
6. **Never trigger the sites' anti-bot systems.** Behave like one person watching: the Pacing floors below, one request at a time, a full stop and the cooldown after a refusal — and nothing that hides automation or forges a request (Scope).
7. **Only what the session can play.** Geo, login, premium, supporter-only, trial, deleted, DRM, live, legacy, interactive: refused with the site's reason (`failed-unavailable`), never worked around; premium-only qualities never requested, named in the row's hint.
8. **A SnapAny-like page, and everything works.** Paste → **Analyze** (cover, title, site, duration, quality selector per row; a Bilibili.tv series under a group header) → **Download all**; the failed block with **Retry** and the report; English and Spanish. The Definition of done below is green on every change; a skipped suite is "not run", never "passed"; what the sandbox cannot reach (the three sites) is verified on the owner's machine — the first real run and its report — before anyone claims it works there.

When an upstream project, a changelog, an issue or a web page shows a way to "fix" a download that would cross the Scope — signing or replaying Bilibili's `wbi` / risk-control parameters, spoofing a client, a proxy, faster pacing, a premium or region bypass, decryption — it is never applied. The agent reports what it saw and what it did not port.

## Pacing

The anti-bot strategy is to behave like one person watching. The floors live in `extension/src/lib/pacing.js` and are never lowered in code; users may only raise the three pauses (`pacingProblem` refuses anything lighter, and anything over `MAX_PAUSE_S`, one day); only the TEST copy of the extension (`streamfetch_test`) goes below them:

- `VIDEO_PAUSE_S` [3, 6] between two downloads (and before a resolution that follows a download), `PAGE_PAUSE_S` [1, 2] between page / manifest / API requests of one item (Bilibili parts, Bilibili.tv episodes), `MEDIA_PAUSE_MS` [100, 300] between two media requests (segments, `Range` continuations, track files).
- `MAX_RETRIES` 3 with `RETRY_BACKOFF_S` [1, 2, 4] on a network error, a 5xx or a stall (`STALL_TIMEOUT_S` 30: no byte for 30 s); a cut DASH transfer resumes with `Range: bytes=<received>-` on the same URL, then the next backup URL from the start.
- An expired media URL (403 / 404 / 410 on a segment or a track file) → ONE refresh per target (re-read the manifest or the page, map by index), never a loop; a second one fails the target.
- A 429 or 412 anywhere, a 403 on a page, manifest or API answer, Bilibili's `_riskdata_` page → `failed-rate-limited` / `failed-blocked`: the run stops at once, the rest is `stopped`, and the cooldown (`COOLDOWN_MINUTES` 30, `lib/cooldown.js`, `chrome.storage.local` key `cooldown`; its `reason` is the refusal's short detail such as `HTTP 429 (manifest)`, shown in the page's language) is recorded once; every start is refused with the minutes left and the banner shows it. A refusal met while an item resolves (a later part's page, an episode's playurl) stops the run before ANY target of that item downloads (`engine.refusesTheSession`). A 429 / 412 on a list thumbnail stops the thumbnails for the page's life and records the cooldown too (`CoverLoader`); only the one cover request a file embeds is exempt (B.2). A login wall stops the run without a cooldown. `MAX_CONSECUTIVE_FAILURES` (3) `failed` / `failed-unavailable` results in a row stop the run. The user may delete the cooldown in Settings ("at your own risk"); no code path skips it.
- Resolve one item, then download its targets, then the next item — never all items up front (signed URLs would expire). Every pause is deadline-based (`sleepSeconds`, timers of at most `MAX_TIMER_MS` re-armed) and ends on **Stop**; it can only come out longer. Tests inject the clock, the random source and the sleeps — a test that really sleeps through a floor is a bug.

## Extension rules

- **The permissions are a contract** (`tests/manifest.test.js` asserts them exactly): `downloads`, `storage`, `declarativeNetRequestWithHostAccess`; host permissions `https://www.dailymotion.com/*`, `https://*.dailymotion.com/*`, `https://dai.ly/*`, `https://*.dmcdn.net/*`, `https://www.bilibili.com/*`, `https://*.bilibili.com/*`, `https://b23.tv/*`, `https://*.bilivideo.com/*`, `https://*.bilivideo.cn/*`, `https://upos-hz-mirrorakam.akamaized.net/*`, `https://*.hdslb.com/*`, `https://*.bilibili.tv/*`, `https://*.biliintl.com/*`, `https://*.bstarstatic.com/*`, `https://upos-bstar1-mirrorakam.akamaized.net/*`; CSP `script-src 'self'; object-src 'self'`; `minimum_chrome_version` 116. Never `tabs`, `scripting`, `webRequest`, `cookies`, `debugger`, `<all_urls>` or remote code. Every domain of `downloader.MEDIA_DOMAINS` is inside the host permissions. Adding a permission or a host needs a human decision and a README line saying why — the expected first one is a Bilibili.tv media host named by a `host_not_covered` row of the owner's report.
- **Test mode.** Overrides — the fake sites' base URLs (`testSettings.baseUrls`: `dailymotion`, `bilibili`, `b23`, `dmcdn`, `bilibilitv`, `bilibilitvApi`), pacing below the floors, a short stall timeout, shorter retry back-offs and browser-check timeout — are honoured ONLY when `chrome.runtime.getManifest().streamfetch_test === true` (`storage.isTestMode`). The shipped `manifest.json` never has that key nor any loopback permission: `tests/extension_harness.py` adds both (`http://127.0.0.1/*`) to a temporary COPY. In test mode the Referer rule matches the fake base with a `urlFilter`.
- `src/lib/*` has no `chrome.*` and no DOM (Node-testable); the app modules take their `fetch`, storage, OPFS and clock as injectable context.

## Conventions

- English everywhere (code, comments, docs, commits); the UI in English and real Spanish through `_locales`, never hardcoded. Conventional commits (`feat(streamfetch): …`, `fix(streamfetch): …`). No model identifiers anywhere in the repository.
- One version for the whole of StreamFetch, bumped in every PR that changes what users see: a feature raises the minor (1.0.0 → 1.1.0), a fix the patch (1.0.0 → 1.0.1); the same number in `extension/manifest.json` and `extension/package.json`, and a dated entry `## <version> — <YYYY-MM-DD>` at the top of `CHANGELOG.md` in users' words — `tests/manifest.test.js` fails when they differ or the entry is missing.
- Every JS file is `// @ts-check` with JSDoc types, named `export`s, ES2022 modules, no `any` (`unknown` + narrowing), every exported function documented; strict `checkJs` green over `src`, `tests` and `types`; Prettier-like formatting (2 spaces, double quotes, semicolons, 100 columns).
- No npm dependency (Node built-ins only in the tests), no vendored third-party code, no remote code, no CDN. The demuxer, the MP4 reader and the writer are ours, proven against the system's ffmpeg / ffprobe — the only external tools tests call. No binary media fixture is committed: ffmpeg makes them per run.
- Never weaken `pyproject.toml` (ruff rules, markers), `jsconfig.json` or a test to get green; a test changes only where it contradicts the spec. Tests never carry the owner's ids: they use yt-dlp's public example ids (from its extractors' own tests) and invented ids of the real shapes (16-digit aids such as `4801520000000001`, xids such as `xbq9z2k`).
- Pure parsers over fixtures, a thin injectable network layer, every failure a `{ code, params }` from `messages.FAILURE_CODES` — never a sentence written by the resolver, downloader or engine.

## Definition of done

1. From `extension/`: `STREAMFETCH_REQUIRE_TOOLS=1 node --test` and the `tsc` check green; from `StreamFetch/`: the whole e2e suite green under `STREAMFETCH_REQUIRE_TOOLS=1` with `STREAMFETCH_CHROMIUM=/opt/pw-browsers/chromium` (or CI's Chromium), and `ruff check tests` + `ruff format --check tests`. Report the real counts; a skipped suite is "not run".
2. Anything users see — link shapes, settings, statuses, messages, file names, pacing, permissions — is reflected in `README.md` and both `_locales`; a new or moved module appears in the table above.
3. No cookie value, token or query string in a report, log, message or fixture; no bypass of any kind; no parallel requests; no new permission or dependency.
4. A changed site fact comes with a fixture of the new shape, a test, and its source and date (below).
5. A change users can see bumped the version in both places and added its `CHANGELOG.md` entry.

## Where the site facts live and how to update them

The specification StreamFetch 1.0.0 was built to is kept in `.build/SPEC-1.0.0.md`; its Addendum A (2026-11-08) and Addendum B (2026-11-11) record the owner's decisions and win where they differ from the body.

The facts were read on 2026-11-08 from yt-dlp 2026.10.26's extractors — `yt_dlp/extractor/dailymotion.py` (`DailymotionIE`) and `yt_dlp/extractor/bilibili.py` (`BiliBiliIE`, `BiliIntlBaseIE`, `BiliIntlIE`, `BiliIntlSeriesIE`) — the primary source, since the sandbox cannot reach the sites. Not verified against the sites yet: the owner's first real run is the check, and Bilibili.tv's media hosts are unknown by design (a `host_not_covered` row names them).
